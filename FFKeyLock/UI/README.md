# 原生界面结构

界面保持 C++20 / Win32 + GDI，不引入浏览器、托管运行时或后台绘制循环。应用自己的客户区使用同一套主题绘制；原生控件继续负责输入状态、Tab 导航与无障碍语义。文件选择器、消息框及系统标题栏由 Windows 管理。

| 模块 | 职责 |
|---|---|
| `../ThemeManager` | 配色、字体、高对比度与标题栏，不接管控件消息 |
| `Rendering/NativeControls` | 按钮、原生复选框、标签、下拉框、输入框边框、滚动条的统一绘制适配 |
| `Rendering/Surface` | 容器背景、圆角面板、背景角色继承与统一失效入口 |
| `Controls/ScrollView` | 圆角外层、内缩固定视口、单一内容子窗口、滚轮累积、滚动条、焦点可见性 |
| `Library/GameLibraryView` | 游戏库与运行中程序共用的两行列表、空白区、滚动条、图标缓存 |
| `Menu/MenuBar` | 客户区菜单入口、Alt / F10 / Alt 助记键、方向键导航 |
| `Menu/PopupMenu` | 原生 HMENU 的临时主题装饰，Windows 负责弹出菜单交互与子菜单 |
| `Menu/AppMenus` | 主菜单、托盘菜单的命令结构 |
| `Profiles/ProfileEditor` | 编辑草稿、键位和输入法选项、脏状态、本地测试反馈 |
| `Main/MainContentView` | 搜索、选择、保存/放弃/取消、复制粘贴，协调编辑器与列表 |
| `Windows/RunningProgramPicker` | 运行中程序枚举与选择 |

## 绘制约定

- 容器 `WM_PAINT` 必须填充整个客户区背景；仅在 `WM_ERASEBKGND` 返回 TRUE 并不能消除旧像素。`WM_PRINTCLIENT` 共用相同绘制路径。
- 主要滚动区由 `UI::MarkPanel` 标记，统一使用面板底色、12 DIP 圆角和 1 个物理像素的低对比边框。子控件通过 `BackgroundBrush/BackgroundColor` 继承背景；只给游戏库和配置区加外框，不给每层内容套框。几何与颜色规则集中在 `ThemeManager`，普通按钮/输入框使用 6 DIP 圆角。
- `ScrollView` 外层负责边框，内缩 8 DIP 的 `FFKeyLockScrollViewport` 裁剪移动的 `FFKeyLockScrollContent`；原生滚动条与内层视口并列，不能覆盖四角。列表采用相同内缩布局。8 DIP 滑块保留 16 DIP 原生命中区域，并进入 Tab 顺序；底部留白由外层绘制。
- `ScrollView` 只改变内容窗口位置。使用 `SWP_NOREDRAW | SWP_NOCOPYBITS` 后让整个视口及子控件失效；不要复制已被裁剪的旧图像，不使用 `WS_EX_COMPOSITED` 叠加第二套缓冲。
- 布局仅在尺寸、DPI、语言、展开状态等变化时运行。滚动不得重新计算键位尺寸、重建控件或重建字体。
- 每个可绘制控件拥有自己的全部背景。标签不依赖透明背景；列表绘制必须包括没有条目的尾部。编辑框文字仍由原生编辑控件绘制，显式提供背景和文字颜色。单行编辑框创建时不带 `WS_BORDER`，由适配层预留非客户区并绘制圆角边框，避免原生控件缓存边框样式后补画第二层直角框。
- 保留 `BS_AUTOCHECKBOX` 和原生勾选状态，不将复选框替换成失去语义的普通按钮。子类绘制不得接管普通按键、鼠标命中或改变草稿。
- 原生 `SCROLLBAR` 的悬停和 `SBM_*` 消息可能绕过 `WM_PAINT` 直接绘制。适配层处理主题悬停，将位置更新转为不绘制的状态更新，再同步绘制主题画面。绘制前先在离屏缓冲调用原生 `WM_PRINTCLIENT`，让系统计算滑块命中/无障碍几何；仅跳过原生绘制会留下零尺寸滑块。原生拖动中的 `WM_CTLCOLORSCROLLBAR` 提前绘制主题画面并裁剪该 DC 的后续系统补画（测量阶段避免递归）；不能先让系统画一帧，再异步修补。原生控件继续处理滑块捕获、拖动与键盘输入。
- `ComboLBox` 保留原生选项、键盘导航和无障碍语义。组合框创建时不设置 `WS_VSCROLL`，列表客户区内放置统一主题的原生 `SCROLLBAR` 子窗口，避免非客户区的系统补画；范围和位置随列表与组合框操作同步。列表捕获期间转发滚动条命中；滑块原生跟踪结束或箭头松开后，仅在弹层仍打开且窗口活动时恢复列表捕获，不在 `WM_CAPTURECHANGED` 中夺回捕获。关闭释放捕获，适配状态随列表窗口销毁。
- 系统箭头的按下补画不经过 `WM_CTLCOLORSCROLLBAR`。滚动条适配层处理箭头/轨道按下、捕获与定时重复，发送标准 `WM_VSCROLL`；移出原命中区域停止重复，松开或取消时清理定时器。滑块拖动、键盘输入与无障碍几何继续使用原生控件。
- 原生菜单会在 `WM_DRAWITEM` 后再画子菜单箭头。`PopupMenuTheme` 统一画箭头并裁剪当前行的系统补画区域；每次进入绘制先清除上一行的显式裁剪，保留系统可见区域。
- `MenuBar` 拥有菜单树，弹出时由 `PopupMenuTheme` 临时设置颜色和 owner-draw 数据，关闭后恢复。弹出期间收到菜单更新必须延后替换，不能销毁活动菜单。
- 图标只在填充列表时读取并缓存，不能在绘制或输入钩子中提取。GDI 对象明确配对释放；持有子控件回调数据的对象至少存活到子窗口销毁之后。
- 旧界面在 `../../archive/legacy-ui`，仅保留历史代码，不参与项目或测试编译；不要从该目录重新引入另一套绘制入口。

## 验证

`tests/RegressionTests.cpp` 覆盖状态、配置、按键配对及隐藏编辑器的布局/DPI/草稿。`tests/UIRenderingTests.cpp` 在独立可见窗口中比较真实客户区像素：操作后画面必须与完整重绘相同，并检查空列表、弹出菜单和下拉框颜色；另在消息处理后、队列重绘前及原生拖动循环内取样，检查滑块几何/悬停/按下颜色、四角/底部背景、空列表、Home/End/Page Down 并捕捉滚动条瞬时闪烁，统计子菜单箭头在普通/高亮状态下是否唯一。测试使用自己的数据，可按 Esc 中止；不修改系统主题或日常配置。

完整命令及实际覆盖边界见 [验证记录](../../tests/VERIFICATION.md)。像素比较不能替代真实跨屏 DPI、系统高对比度、实体键盘和游戏验收。
